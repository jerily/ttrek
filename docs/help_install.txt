Usage: install [options] ?package_A@version_range_A? ?package_B@version_range_B? ?...?

Available options:
    -registry SOURCE - append a local directory or HTTP(S) API URL; repeat to set lookup order
    -add-pubreg - append the public default after explicit or saved sources (synced local copy, otherwise API)
    -y - answer yes to the installation confirmation
    -force - reinstall requested packages even when unchanged, plus their transitive reverse dependencies
    -strategy STRATEGY - dependency resolution: favored (default), latest, or locked
    -fail-verbose - show the build log when installation fails
    -save-dev, -D - save explicitly named packages in devDependencies
    -u - install using user mode (~/.local)
    -g - install using global mode (/usr/local/ttrek)
    default - If no mode is specified, install using local mode (./ttrek-venv)

package is the package name e.g. twebserver

version_range is a comma-separated list of operator (op) and version pairs where op is:

^  - caret operator accepts all versions that have the same major version
>= - greater than or equal operator ...
>  - greater than operator ...
<= - less than or equal operator ...
<  - less than operator ...
== - equals operator ...

Examples:
    twebserver@1.47.37
    twebserver@^1.47.37
    "twebserver@>=1.47.37,<1.50.0"

The first registry containing a package supplies its versions and recipe.
Only an absent package advances to the next registry; other errors stop lookup.
Explicit sources replace the saved list and defaults for this invocation.

Without package arguments, install resolves both dependencies and devDependencies,
runs the project's build instructions, and preserves each dependency's section.
-save-dev affects only explicitly named packages; it also moves an existing
runtime dependency to devDependencies without requiring a rebuild. Transitive
packages are not added to either direct-dependency section.

Strategies:
    favored - prefer versions recorded in the lockfile that satisfy the requirements
    latest  - prefer newest compatible versions for requested packages; keep
              other locked versions when compatible with the requested change
              (without package arguments, consider the entire dependency graph)
    locked  - require locked versions for packages already in the lock file

New or changed packages and their transitive reverse dependencies are installed
in dependency order. Unchanged forward dependencies and unrelated packages are
not rebuilt. With no package arguments, -force targets all direct dependencies.
The preInstall and postInstall project hooks run around the install operation.

Examples:
    ttrek install -y twebserver
    ttrek install -save-dev cmake
    ttrek install -D ninja
    ttrek install -force web-wiki
    ttrek install -strategy latest web-blog

A package name must appear in only one of dependencies or devDependencies.
Manifests listing the same name in both sections are rejected.

The lockfile records resolved versions; it is not proof of installation.
ttrek-venv/ttrek-manifest.json records installed versions, files, build flags,
and dependencies. Missing installations or files are rebuilt even when locked.
Older manifests without build metadata are refreshed by reinstalling once.
